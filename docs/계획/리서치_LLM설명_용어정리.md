## 1. LLM(대규모 언어모델) 작동원리 - "초고속 확률 계산기"

### 한 줄 요약
LLM은 **"지금까지의 문맥을 보고, 다음에 올 단어를 확률로 예측하는 초고속 계산기"**입니다.

### 일상 비유로 이해하기

**스마트폰 자동완성과 같은 원리입니다.**
카카오톡에서 "오늘 점심"이라고 치면 자동완성이 "뭐 먹을까?"를 추천하죠? LLM도 정확히 같은 원리입니다. 다만 스마트폰은 이전 단어 1~2개만 보지만, LLM은 수만 단어의 문맥을 한꺼번에 보고 판단합니다.

**작동 과정을 3단계로 설명하면:**

1. **학습 단계 (준비)**: 인터넷의 수십억 개 문서(뉴스, 책, 위키백과 등)를 읽으며 "이 단어 다음에 어떤 단어가 자주 오는지" 패턴을 익힙니다. 마치 도서관의 모든 책을 읽은 사람처럼 됩니다.

2. **예측 단계 (계산)**: 사용자가 질문을 입력하면, 학습한 패턴을 바탕으로 "다음 단어로 가장 적절한 것"의 확률을 계산합니다.
   - 예: "광진구의 인구는" → "약(85%)" / "대략(10%)" / "현재(5%)"
   - 가장 높은 확률의 단어를 선택하고, 그 단어를 붙인 뒤 다시 다음 단어를 예측합니다.

3. **생성 단계 (출력)**: 이 과정을 수백~수천 번 반복하면 문장이 완성됩니다. 마치 **릴레이 소설을 혼자 쓰는 것**과 같습니다.

**중요한 점:**
- LLM은 "이해"하는 것이 아니라 **"패턴 매칭"**을 합니다
- 그래서 가끔 그럴듯하지만 틀린 답(할루시네이션)을 만들어내기도 합니다
- 같은 질문에 매번 조금씩 다른 답이 나오는 것도 확률적으로 선택하기 때문입니다

## 2. AI 에이전트 vs 단순 LLM - "비서"와 "백과사전"의 차이

### 한 줄 요약
LLM이 **"질문에 답하는 똑똑한 백과사전"**이라면, AI 에이전트는 **"스스로 판단하고 행동하는 비서"**입니다.

### 핵심 차이

| 구분 | 단순 LLM | AI 에이전트 |
|------|----------|-------------|
| 비유 | 백과사전 / 상담사 | 비서 / 실행자 |
| 하는 일 | 질문에 대답 | 목표를 향해 스스로 판단하고 실행 |
| 예시 | "회의실 예약 방법 알려줘" → 방법 설명 | "회의실 예약해줘" → 직접 시스템에 접속해서 예약 완료 |
| 도구 사용 | 못 함 (말만 함) | 가능 (파일 열기, 검색, 코드 실행 등) |
| 기억 | 대화 끝나면 잊음 | 이전 작업 맥락 기억 가능 |

### 현재 트렌드: "에이전트의 시대"

2025~2026년은 **"에이전트의 해"**로 불립니다. 전 세계 AI 기업들이 단순히 "대답하는 AI"를 넘어 "일을 해주는 AI"로 빠르게 전환하고 있습니다.

**주요 AI 에이전트 코딩 도구:**

| 회사 | 에이전트 | 특징 |
|------|----------|------|
| **Anthropic** | Claude Code | 터미널에서 코드 읽기, 수정, 실행을 자율적으로 수행. 여러 에이전트를 동시에 띄워 병렬 작업 가능. 2025년 출시 6개월 만에 연 매출 10억 달러 돌파 |
| **OpenAI** | Codex | 클라우드 환경에서 독립적으로 코드 작성, 테스트, 수정. GPT-5.3-Codex 모델 탑재. 최대 7시간 이상 자율 작업 수행 가능 |
| **Google** | Jules | GitHub와 연동, Google Cloud 가상머신에서 자율적으로 코드 수정. Gemini 3 Pro 모델 기반 |

**시장 규모**: AI 에이전트 시장은 2025년 76.3억 달러에서 2030년 503.1억 달러로 성장 전망 (연평균 45.8% 성장)

## 3. 바이브 코딩(Vibe Coding)이란?

### 정의
코드를 직접 작성하지 않고, **AI에게 자연어(일상 말)로 지시하여 소프트웨어를 만드는 방식**입니다.

### 안드레이 카파시(Andrej Karpathy)의 원래 정의

OpenAI 공동창업자이자 Tesla 전 AI 총괄인 안드레이 카파시가 **2025년 2월** X(구 트위터)에 올린 글에서 처음 사용한 용어입니다.

원문(번역):
> "저는 이것을 **'바이브 코딩'**이라 부릅니다. 분위기에 완전히 몸을 맡기고, 코드가 존재한다는 사실조차 잊는 겁니다. (...) 저는 SuperWhisper(음성인식)로 말만 합니다. 키보드를 거의 안 쳐요. 귀찮아서 간단한 것도 AI에 시킵니다. 변경 사항을 직접 읽지도 않고 전부 수락합니다. 에러가 나면 에러 메시지를 그냥 복붙해서 코멘트 없이 보냅니다."

카파시 본인은 1년 후인 2026년 2월 회고에서 이 트윗을 **"샤워하다 떠오른 생각을 그냥 날린 트윗"**이라고 표현했으나, 이 용어는 폭발적으로 확산되어 **위키백과 문서까지 생성**되었습니다.

### 실제로 어떻게 작동하나?

1. 사용자가 **말이나 글로 원하는 기능을 설명**합니다
   - 예: "광진구 문화행사를 날짜순으로 정렬하는 웹페이지 만들어줘"
2. AI가 **코드를 자동 생성**합니다
3. 결과를 확인하고, 수정이 필요하면 **다시 말로 지시**합니다
   - 예: "표 색상을 파란색으로 바꾸고, 검색 기능 추가해줘"
4. 이 과정을 반복하여 완성합니다

### 바이브 코딩의 진화: 에이전틱 엔지니어링

카파시는 2026년 2월, 바이브 코딩의 다음 단계로 **"에이전틱 엔지니어링(Agentic Engineering)"**이라는 용어를 제시했습니다:
- **바이브 코딩**: 개인 프로젝트, 프로토타입에 적합. 코드를 읽지 않고 감으로 진행
- **에이전틱 엔지니어링**: 전문적 AI 협업 개발. AI 에이전트를 지휘하되 품질 감독을 병행

## 5. 기술 용어를 쉬운 비유로 이해하기

### RAG (검색 증강 생성)

**비유: 오픈북 시험**

일반 LLM은 **암기 시험**과 같습니다. 학습할 때 읽은 내용만으로 답합니다. 그래서 최신 정보나 내부 자료에 대해서는 엉뚱한 답을 할 수 있습니다.

RAG는 **오픈북 시험**입니다. 질문을 받으면 먼저 관련 자료(문서, DB 등)를 검색해서 찾아본 뒤, 그 자료를 참고하여 답변합니다.

```
[일반 LLM]  질문 → (기억에서 꺼냄) → 답변 (틀릴 수 있음)
[RAG]       질문 → 관련 문서 검색 → 문서 참고하여 답변 (정확도 향상)
```

**행정 활용 예시**: 광진구 조례집, 업무매뉴얼을 RAG로 연결하면 → AI가 "이 민원은 어떤 조례에 해당하나요?"에 정확히 답변 가능

### 벡터 DB (벡터 데이터베이스)

**비유: 의미별로 정리된 도서관**

일반 데이터베이스는 **가나다순 정리**입니다. "사과"를 검색하면 "사과"라는 글자가 들어간 것만 찾습니다.

벡터 DB는 **의미별 정리**입니다. "사과"를 검색하면 "과일", "애플", "빨간 열매" 등 **의미가 비슷한 것**도 함께 찾아줍니다.

이것이 가능한 이유는 모든 텍스트를 **수백 개의 숫자(벡터)**로 변환하여 의미의 "좌표"를 만들기 때문입니다. 의미가 비슷한 단어일수록 가까운 좌표에 위치합니다.

**RAG와의 관계**: RAG가 "오픈북 시험"이라면, 벡터 DB는 그 **오픈북에서 관련 페이지를 빠르게 찾아주는 색인** 역할입니다.

### MCP (모델 컨텍스트 프로토콜)

**비유: USB-C 포트 / 만능 리모컨**

스마트폰을 충전할 때 예전에는 기기마다 충전 단자가 달랐습니다(아이폰용, 삼성용, LG용...). USB-C가 등장하면서 하나의 케이블로 모든 기기를 충전할 수 있게 되었죠.

MCP는 **AI 세계의 USB-C**입니다. AI가 외부 도구(데이터베이스, 파일 시스템, 웹 API 등)에 접속할 때 **하나의 표준 방식**으로 연결할 수 있게 해주는 규격입니다.

```
[MCP 이전]  AI ↔ 도구A (전용 연결)
            AI ↔ 도구B (또 다른 전용 연결)
            AI ↔ 도구C (또 다른 전용 연결)  → 매번 새로 개발 필요

[MCP 이후]  AI ↔ MCP(표준 규격) ↔ 도구A, 도구B, 도구C  → 한번 만들면 재사용
```

**현황**: Anthropic이 2024년 11월 공개한 오픈소스 표준으로, 2025년 12월 Linux Foundation에 기증. OpenAI, Google, Microsoft 등이 모두 채택하여 사실상 업계 표준이 됨. 월 9,700만 건 이상의 SDK 다운로드 기록.

**행정 활용 예시**: MCP로 광진구 내부 시스템(인사, 재정, 민원)을 AI에 연결하면, AI가 여러 시스템의 데이터를 통합 조회/처리 가능

### 프롬프트 엔지니어링

**비유: AI에게 업무 지시하는 기안문 작성법**

새로 온 직원에게 업무를 맡길 때 "알아서 해"라고 하면 엉뚱한 결과가 나오죠. **구체적으로 지시**할수록 원하는 결과가 나옵니다.

```
[나쁜 지시]  "보고서 써줘"
[좋은 지시]  "광진구 2025년 문화행사 실적을 표로 정리하고,
             전년 대비 증감률을 포함하여 A4 2쪽 분량으로 작성해줘.
             대상 독자는 구청장이고, 핵심 성과 3가지를 먼저 요약해줘."
```

### 할루시네이션 (Hallucination)

**비유: AI의 "지어내기"**

시험에서 모르는 문제가 나왔을 때, 빈칸을 두기보다 **그럴듯하게 지어내서** 쓰는 것과 같습니다. AI도 모르는 것을 "모른다"고 하지 않고, 학습 패턴에 기반해 그럴듯한 답을 만들어냅니다.

그래서 AI 답변은 반드시 **사실 확인(팩트체크)**이 필요합니다. 특히 법률, 통계, 인명 등 정확성이 중요한 정보는 원본 자료와 대조해야 합니다.

### 파인튜닝 (Fine-tuning)

**비유: 신입 공무원의 부서 배치 후 OJT**

대학을 졸업한 신입 공무원(= 사전 학습된 LLM)이 광진구 문화체육과에 배치되면, 그 부서만의 업무 방식, 용어, 절차를 추가로 배웁니다. 이것이 파인튜닝입니다. 기본 지식은 유지하면서 **특정 분야에 맞게 추가 훈련**하는 것입니다.

> **출처**: [AWS - What is RAG](https://aws.amazon.com/what-is/retrieval-augmented-generation/), [Elastic - 검색 증강 생성이란](https://www.elastic.co/kr/what-is/retrieval-augmented-generation), [IBM - What is MCP](https://www.ibm.com/think/topics/model-context-protocol), [Wikipedia - Model Context Protocol](https://en.wikipedia.org/wiki/Model_Context_Protocol), [MCP Explained Simply](https://dasroot.net/posts/2026/03/model-context-protocol-mcp-explained/)

## 부록: 용어 정리표

| 용어 | 쉬운 비유 | 한 줄 설명 |
|------|-----------|------------|
| LLM | 초고속 확률 계산기 | 다음 단어를 확률로 예측하여 문장을 만드는 AI |
| AI 에이전트 | 자율 행동 비서 | 스스로 판단하고 도구를 써서 일하는 AI |
| 바이브 코딩 | 말로 하는 프로그래밍 | AI에게 자연어로 지시하여 코드를 만드는 방식 |
| RAG | 오픈북 시험 | AI가 외부 자료를 검색 후 참고하여 답변하는 기술 |
| 벡터 DB | 의미별 도서관 | 텍스트의 "의미"를 기준으로 검색하는 데이터베이스 |
| MCP | AI의 USB-C | AI가 외부 도구에 연결하는 표준 규격 |
| 프롬프트 | AI 업무 지시문 | AI에게 입력하는 질문이나 명령 |
| 할루시네이션 | AI의 지어내기 | AI가 사실이 아닌 내용을 그럴듯하게 생성하는 현상 |
| 파인튜닝 | 부서 배치 후 OJT | 기본 AI를 특정 분야에 맞게 추가 훈련하는 것 |
| 토큰 | AI가 읽는 단위 | AI가 텍스트를 처리하는 최소 단위 (대략 한글 1글자 = 1~2토큰) |
