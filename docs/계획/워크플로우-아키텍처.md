> 작성일: 2026-03-24 | 기준 커밋: 1f2a7da

## 앱 아키텍처 (3-Layer)

```
┌─────────────────────────────────┐
│  React (Tauri WebView)          │  ← UI + 상태 관리
│  usePipeline / useSidecar       │
├─────────────────────────────────┤
│  Rust (Tauri Core)              │  ← IPC 브릿지 + 프로세스 관리
│  SidecarManager + JSON-RPC      │
├─────────────────────────────────┤
│  Python Sidecar (별도 프로세스)    │  ← AI 처리 엔진
│  Gemini API + PyMuPDF + Playwright│
└─────────────────────────────────┘
```

앱 실행 시 Tauri가 Python sidecar(`eduplan-sidecar.exe`)를 자식 프로세스로 실행하고, **stdin/stdout JSON-RPC 2.0**으로 통신. 프론트엔드의 모든 AI 호출은 `sidecar.call(method, params)` → Rust `SidecarManager` → Python `rpc_handler.dispatch()` 순으로 전달.

## 메인 파이프라인 (좌측 "파이프라인" 탭)

사전기획 적정성 검토의 핵심 업무 흐름을 **6단계 자동화**:

### Step 1. 문서 가져오기 (`idle` → `import`)

사용자가 사전기획 서류(HWP/HWPX/PDF)를 선택하는 단계.

- **파일 선택**: Tauri 네이티브 다이얼로그로 개별 파일 선택 → `src/App.tsx:104`
- **폴더 선택**: 폴더 통째로 → Python `list_files` RPC가 `.hwp/.hwpx/.pdf`만 필터 → `src/App.tsx:134`
- UI: `src/components/pipeline/ImportStep.tsx` — 파일 목록 표시, 드래그앤드롭, 삭제 가능

### Step 2. OCR 변환 (`import` → `ocr`)

HWP/PDF를 AI가 읽을 수 있는 마크다운으로 변환하는 단계.

- **흐름**: `handleStartOcr` → `pipeline.startOcr(sidecar.call)` → RPC `ocr_files`
- **Python 내부** (`python-sidecar/src/mvp1_converter/pipeline.py`):
  1. **HWP → PDF**: `hwp_to_pdf.py`가 한컴오피스 COM 자동화(`pyhwpx`)로 변환
  2. **PDF → 마크다운**: `ocr_engine.py`가 PDF를 페이지별 이미지로 렌더링(PyMuPDF, 150 DPI) → Gemini Vision API로 텍스트/표 인식 → 마크다운으로 저장
- **병렬 처리**: `max_workers=3` 스레드풀로 동시 OCR
- **진행 상황**: Python이 JSON-RPC notification 전송 → Rust가 Tauri 이벤트로 포워딩 → React `pipeline:progress` 리스너가 UI 업데이트
- UI: `src/components/pipeline/OcrProgressStep.tsx` — 프로그레스 바 + 실시간 로그

### Step 3. AI 페이지 태깅 (`ocr` → `tagging`)

OCR 완료 후 자동으로 시작. PDF 각 페이지를 **9개 테마**로 분류하는 단계.

- **흐름**: `startOcr` 내에서 OCR 성공 후 자동으로 RPC `tag_pages` 호출
- **Python 내부** (`python-sidecar/src/mvp1_converter/page_tagger.py`):
  1. PDF를 PyMuPDF로 열어 페이지별 썸네일(150 DPI PNG) 렌더링
  2. **5페이지씩 배치**로 Gemini Vision에 전송
  3. 프롬프트: "아래 페이지 이미지들을 분석하고 테마를 선택하세요"
  4. 응답 JSON 파싱 → `{pageNum, sourceFile, theme, confidence, confirmed}` 배열 반환
- **9개 테마**: 학급수 및 학생수, 각종 면적, 사업 유형, 기간, 발주 방식, 사업비, 스페이스프로그램, 설문, 기타
- **재시도**: 429/503/quota 에러 시 지수 백오프 (최대 3회), JSON 파싱 실패도 재시도

### Step 4. 태그 리뷰 (`tagging` → `review`)

AI 분류 결과를 사용자가 확인/수정하는 단계.

- UI: `src/components/pipeline/TagReviewStep.tsx`
- 각 페이지의 AI 추천 테마 + confidence 표시
- 사용자가 잘못된 테마를 수동으로 바꿀 수 있음
- **확인 버튼** 클릭 → `handleConfirmTags` → `pipeline.startExtract(sidecar.call)`

### Step 5. 페이지 추출 + 분석 (`review` → `extract` → `analyze`)

확정된 태그 기반으로 PDF를 테마별로 분리하고 AI 분석하는 단계.

- **추출** (RPC `extract_pages`):
  - `python-sidecar/src/mvp2_extractor/extractor.py` `run_from_tags()` 호출
  - 확정된 태그 배열을 받아 테마별 폴더에 해당 페이지만 추출
  - 예: "학급수 및 학생수" 태그된 페이지들 → `a_학급수 및 학생수/` 폴더에 PDF 추출

- **1차 요약** (RPC `summarize`):
  - `python-sidecar/src/mvp3_analyzer/summarizer.py` `run_step1()`
  - 테마별 추출된 마크다운 파일 각각을 Gemini로 개별 요약
  - 모델: `gemini-3.1-flash-lite-preview` (비용 효율)

- **2차 통합분석** (RPC `integrate`):
  - `python-sidecar/src/mvp3_analyzer/integrator.py` `run_step2()`
  - 1차 요약들을 하나로 합쳐서 **교차 분석 리포트** 생성
  - `num_variants=2`로 2개 버전의 분석 생성 (temperature=0.7)

### Step 6. 완료 (`analyze` → `complete`)

- UI: `src/components/pipeline/ResultStep.tsx`
- 처리 결과 요약 (성공/실패 건수, 경고)
- **"출력 폴더 열기"** 버튼 → `sidecar.call("open_folder")` → OS 탐색기로 결과 폴더 오픈

## 자료 수집 도구 (우측 "자료수집" 탭)

사전기획 검토 의견서 작성에 필요한 **공공데이터 7종을 자동 수집**. Playwright 브라우저 자동화 기반.

| 도구 | 데이터 | 사이트 | 용도 |
|------|--------|--------|------|
| 학교알리미 | 학교 공시정보 (학급수, 학생수, 교원수 등) | schoolinfo.go.kr | 현황 파악 |
| 세움터 | 건축물대장 (면적, 층수, 구조) | eais.go.kr | 시설 현황 |
| 토지이음 | 토지 용도지역/이용계획 | eum.go.kr | 부지 분석 |
| 학령인구 | 지역별 연령별 인구 | jumin.mois.go.kr | 수요 예측 |
| 국가유산 | 문화유산 존재 여부 | gis-heritage.go.kr | 부지 제약 확인 |
| 설계대가 | 건축사 설계비 산출 | kirahub.kira.or.kr | 사업비 산정 |
| 학구도 | 학교 통학구역 | schoolzone.emac.kr | 배치 검토 |

### 작동 방식

1. 사용자가 도구 선택 → 입력값 입력 (학교명, 주소 등) → "수집 시작"
2. `sidecar.call("browser_tool", {tool: "schoolinfo", params: {school_name: "광남고등학교"}})`
3. Python `browser_tools/` 각 도구가 Playwright로 headless 브라우저 실행
4. 사이트 접속 → 검색 → 결과 파싱 → JSON + 파일(JSON/TXT/CSV) 저장
5. 로그인 필요 사이트(세움터, 설계대가)는 **headed 브라우저 전환** → 사용자가 직접 로그인 → 자동 감지 후 계속 수집

### 수집 이력 + 통합 리포트

- 완료된 수집 결과가 `collections` 배열에 누적
- "수집 내역" 클릭 → 타임라인 뷰 + **마크다운 통합 리포트** 자동 생성
- 리포트 복사/파일 저장 가능 → 의견서 작성에 바로 활용

## 공통 시스템

### 취소(Cancel) 시스템

전 구간에서 **graceful cancellation** 지원:
- 프론트엔드: `cancelledRef.current = true` → 모든 async 경계에서 체크
- Rust: `send_fire_and_forget`로 Python에 즉시 전달 (deadlock 방지)
- Python: `threading.Event` — 각 메서드가 루프마다 `cancel_event.is_set()` 체크, `cancel_event.wait(timeout)`으로 대기 중 즉시 깨어남

### 설정 관리

- **API 키**: 설정 모달에서 입력 → `sidecar.call("set_api_key")` → 환경변수(`GEMINI_API_KEY` + `GOOGLE_API_KEY`) + `.env` 파일 영속화
- **모델 선택**: OCR용(`gemini-3-flash-preview`)과 분석용(`gemini-3.1-flash-lite-preview`) 분리 — 비용/성능 트레이드오프
- **테마**: 라이트/다크 모드, localStorage 영속화
- **YAML 설정**: `python-sidecar/config/settings.yaml` — DPI, 병렬 스레드, 타임아웃, 재시도 등 외부화
