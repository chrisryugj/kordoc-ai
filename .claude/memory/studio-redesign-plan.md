# KorDoc Studio UI 개편 플랜 (Phase R)

> 2026-06-13 작성 (집 PC). 회사 PC의 구 `kordoc-studio-plan.md`(gitignore 로컬)를 대체하는 신규 플랜.
> **이 파일은 git 추적됨** (`.claude/memory/`) — 어느 PC에서든 이 플랜이 단일 진실 소스.

## 최종 목표 (사용자 정의)

1. **시험지 자동완성** — 시험지(HWPX)를 열어 문항을 AI로 생성/수정하고 서식 그대로 저장
2. **양식 자동 채움** — 양식을 보여주면 텍스트를 자동으로 채워 공문서를 쉽게 완성

## 현재 구조의 문제

- Workspace = 파일 드롭 + 액션 카드 그리드. FillWizard / DocEditor가 **각각 풀스크린 모달**로 따로 떠서:
  - rhwp WASM 문서 인스턴스를 각자 생성 (채우기↔편집 전환 시 재파싱·재렌더)
  - 채우다가 편집하려면 모달 닫고 다른 모달 열어야 함 — 문서 중심이 아니라 기능 중심
- 시험지/공문서 작업은 "한 문서를 놓고 여러 도구를 번갈아 쓰는" 흐름인데 UI가 이를 막음

## 목표 레이아웃 — 문서 워크벤치

```
┌──────────────────────────────────────────────────────────┐
│ 툴바: 파일명 · undo/redo · 저장/자동저장 상태 · 잠금 토글  │
├────────┬─────────────────────────────┬───────────────────┤
│ 파일    │                             │ 도구 탭            │
│ 목록    │   문서 미리보기 (rhwp SVG)   │ ┌───────────────┐ │
│ (세션)  │   페이지 내비 + 클릭-편집    │ │채우기│편집│AI│변환│ │
│        │                             │ └───────────────┘ │
│        │                             │  활성 탭 패널      │
└────────┴─────────────────────────────┴───────────────────┘
```

- **중앙**: 단일 미리보기 — DocEditor의 클릭-편집/잠금 시각화가 기본 탑재
- **우측 도구 탭**:
  - **채우기**: FillWizard 좌측 폼을 패널로 이식 (스키마 폼, 명부 가져오기, 출처 배지)
  - **편집**: 블록 목록 + capability 사유 목록 (클릭-편집 보조 뷰)
  - **AI**: Phase D 연계 — 참고자료 던지면 Gemini가 필드값 추론 → 채우기 폼에 제안 (시험지 문항 생성도 여기)
  - **변환**: 마크다운/PDF 내보내기, 병합 등 기존 액션
- **좌측**: 가져온 파일 목록 (다중 파일 → 문서 전환), 배치 작업 진입
- 기존 액션 카드 홈은 유지하되 "문서 열기" 시 워크벤치로 진입 (가벼운 배치 변환 사용자 보호)

## 핵심 기술 결정

1. **DocumentSession 컨텍스트** (React Context): 파일 1개당 `{ rhwpDoc, editSessionId, blocks, capabilities, dirty, savedAt }` 단일 보유. FillWizard/DocEditor가 각자 들던 미리보기 상태를 여기로 승격. 사이드카 `edit_*` 세션을 그대로 사용 (form_fill의 dry_run doc_b64도 동일 세션에 반영 가능한지 검토 — 안 되면 fill 후 edit_open 재오픈).
2. **채우기 ↔ 편집 일관성**: form_fill은 stateless라 편집 세션과 바이트가 갈라질 수 있음 → 워크벤치에서는 채우기도 `edit_patch`(셀/문단)로 수렴시키는 게 이상적. v1은 "채우기 적용 시 편집 세션 재오픈"으로 단순화 허용.
3. **frontend-design 스킬 필수 사용** — 제네릭 AI 디자인 회피, 기존 토큰(`var(--color-*)`, ts-* 타이포) 유지.
4. 모달 컴포넌트(FillWizard/DocEditor)는 **삭제하지 말고 패널로 점진 이식** — 회귀 방지.

## 단계

| 주차 | 작업 | 산출물 |
|------|------|--------|
| W1 | 워크벤치 셸: 3-pane 레이아웃 + DocumentSession 컨텍스트 + 미리보기 패널 (DocEditor 이식) | 문서 열기→클릭-편집이 워크벤치에서 동작 |
| W2 | 채우기 패널 이식 (FillWizard 폼 부분) + 채우기→편집 세션 동기화 | 채움+수정이 한 화면에서 |
| W3 | 변환/내보내기 탭 + 좌측 파일 목록 + 홈 진입 흐름 정리 + 디자인 폴리시 | 기존 기능 패리티 |
| W4 | AI 탭 (Phase D): 참고자료 → Gemini 필드값 추론 → 채우기 제안, 시험지 문항 생성 PoC | 목표 ①② 직결 |

## 함정 (이번 세션에서 검증된 것 포함)

- kordoc dist stale이면 `HwpxSession` 미노출 → 본 레포 작업 전 `cd c:\github_project\kordoc && npm run build`
- 사이드카는 esbuild 번들 — kordoc 수정 후 `pnpm build:node-sidecar` + 앱 재시작 필요
- 문단 편집 들여쓰기 소실은 kordoc PR #35에서 수정됨 (전각공백 포함). 머지 전 브랜치: `fix/patch-indent-preserve`
- PUA 글리프(`󰏅`) 문단은 capability=text라도 graceful-skip — UI에서 사유 토스트로 안내됨 (정상)
- 빈 셀은 SVG에 글자가 없어 클릭 불가 — 채우기 패널이 담당 (의도된 분담)
- pnpm 전역 minimum-release-age 7일 → 신규 패키지는 `.npmrc` 예외
